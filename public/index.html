      Choix de conception

      • Hybride, pas seulement des vecteurs. Les vecteurs comprennent les reformulations et les autres langues ; BM25 trouve les codes exacts (NX-409, article 10) que les vecteurs ratent. La fusion RRF garde le meilleur des deux.
      • Reranking. Le cross-encoder lit la question et le passage ensemble : plus précis qu’une similarité de vecteurs, appliqué seulement aux 20 meilleurs candidats.
      • En-tête de contexte. Chaque passage est indexé avec « document › section » : un passage isolé sait de quoi il parle.
      • Citations vérifiées. Chaque phrase doit citer [n] ; l’interface signale les citations inventées et le taux de phrases citées.
      • Mesurer avant d’affirmer. Un jeu de 24 questions étiquetées compare les méthodes (hit@k, MRR), par type de question.

      Sécurité

      • Instructions et liste des modèles fixées côté serveur ; le navigateur n’envoie que la question et les passages, revalidés champ par champ.
      • Les passages sont encadrés comme des données ; une balise injectée est neutralisée. Bouton « document piégé » pour le démontrer.
      • CSP stricte sans script en ligne, HSTS, limitation de débit par IP, code d’accès comparé en temps constant, erreurs du fournisseur jamais renvoyées.

      Limites et suite

      • Index en mémoire du navigateur : parfait jusqu’à quelques milliers de passages. Au-delà : index vectoriel côté serveur (pgvector, Vectorize) avec droits d’accès par document.
      • Pas encore de réécriture des questions de suivi ni d’OCR des PDF scannés.
      • Évaluation de la génération (fidélité aux sources) par un modèle juge : prochaine étape.

      Design choices

      • Hybrid, not vectors only. Vectors understand paraphrases and other languages; BM25 finds exact codes (NX-409, article 10) that vectors miss. RRF fusion keeps the best of both.
      • Reranking. The cross-encoder reads question and passage together: more precise than vector similarity, applied only to the top 20 candidates.
      • Context header. Each passage is indexed with “document › section”, so an isolated passage knows what it is about.
      • Checked citations. Every sentence must cite [n]; the interface flags invented citations and shows the share of cited sentences.
      • Measure before claiming. A labelled set of 24 questions compares the methods (hit@k, MRR), per question type.

      Security

      • Instructions and model list fixed on the server; the browser only sends the question and passages, re-validated field by field.
      • Passages are fenced as data and injected tags are neutralised. The “poisoned document” button demonstrates it.
      • Strict CSP with no inline script, HSTS, per-IP rate limits, constant-time access code check, provider errors never forwarded.

      Limits and next steps

      • In-browser index: ideal up to a few thousand passages. Beyond that: a server-side vector index (pgvector, Vectorize) with per-document access rights.
      • No follow-up question rewriting or OCR of scanned PDFs yet.
      • Generation evaluation (faithfulness to sources) with a judge model: next step.
